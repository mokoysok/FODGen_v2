How the FOD User Guide Generator Works

A guided tour of a Python/Tkinter desktop application that prepares Forms on Download (FOD) user-guide materials from release files, RTF documents, spreadsheets, and form lists.

01 · Orientation

What this application does

The FOD User Guide Generator automates the repetitive work of collecting release files, comparing form lists, identifying additions/deletions/revisions, and updating a user guide. The user enters release details in a desktop form, then the app runs a defined sequence of processing steps in the background.

Input

Release information

Publication number, release number, month/year, a prior ZIP file, the current user guide, and an FT output path.

Process

Document pipeline

RTF files are moved, copied, extracted, converted to text, compared, and organized into reports.

Output

Updated guide + ZIP

The final guide is copied, the release RTF files are zipped, and temporary processing folders are cleaned up.

02 · Architecture

How the project is organized

main.py — application controller

Builds the Tkinter interface, validates inputs, starts worker threads, updates progress, and calls the functions in the correct order.

functions/ — processing modules

Each file owns one focused responsibility: copying, converting, comparing, renaming, reporting, or cleaning files.

requirements.txt — dependencies

Lists Python 3.13 packages such as pandas, openpyxl, Pillow, striprtf, pywin32, Aspose Words, and Auto Py to Exe.

Dynamic application assets

APP_DIR resolves the folder containing main.py during development or the executable when packaged. logo.ico and FOD.png are loaded from there instead of a share drive.

Design pattern: most processing functions accept self. This lets them read values from the GUI fields, such as self.entry1 for the publication number, without duplicating input code in every module.
03 · Main workflow

Generate button: end-to-end flow

1. Enter release details
2. Validate all fields
3. Run processing in a worker thread
4. Update progress through a queue
5. Produce the updated guide

check_path() validates the form and opens a confirmation dialog. If confirmed, it starts run_all_functions() on a background thread. The worker sends status and percentage messages to a queue; the Tkinter main thread reads the queue and safely updates the pop-up and progress bar.

Why a thread?

File copying, Excel work, ZIP extraction, Word automation, and comparisons can take time. A worker thread keeps the window responsive.

Why a queue?

Tkinter widgets should be changed from the main thread. The queue is the safe bridge between the worker and user interface.

Where files go

The processing directory is based on the publication number under the configured FOD network structure; reports are written in its Report folder.

04 · Function topics

Module-by-module learning guide

Open a topic to see the purpose of its functions and where it fits in the workflow.

move_rtf.py — Topic: Archive the current release RTF files
move_rtf_files(self)

Moves eligible RTF files from the current FOD area into the release-specific archive folder, preserving a clean working folder for new output.

copy_ft_output.py — Topic: Bring in FT output files
copy_ftoutput_rtf_files(self)

Reads the FT output path entered in the interface and copies RTF files into the current FOD working location.

extract_zipfile.py — Topic: Unpack the previous release
select_zip_file(self)

Returns the selected ZIP-file path from the GUI.

extract_zip(zip_file, extract_dir)

Uses Python's ZIP support to extract an archive into a specified folder.

extract_zip_action(self)

Creates a folder named after the selected ZIP and extracts the previous release there.

rtf2txt.py — Topic: Convert form-list RTF to readable text
convert_rtf_to_txt_current(self)

Finds the current FORMLIST RTF, converts its RTF markup to plain text with striprtf, and saves Current_FORMLIST.txt.

convert_rtf_to_txt_prev(self)

Performs the same conversion for the extracted previous release and saves Previous_FORMLIST.txt.

formlisttxt2xlsxcitrix.py — Topic: Turn form lists into spreadsheets
formlisttxt2xlsx_current(self)

Parses the current form-list text and produces an Excel representation for later matching.

formlisttxt2xlsx_prev(self)

Creates the equivalent Excel file from the previous release's form-list text.

rename_rtf_frm_xlsx.py — Topic: Name RTF files from form-list data
rename_rtf_from_excel1(self)

Uses Current_FORMLIST.xlsx to map current RTF filenames to form numbers and copies renamed files to MODIFIED.

rename_rtf_from_excel2(self)

Applies the same mapping approach to the previous release's RTF files.

revisionsforms.py — Topic: Compare revised forms
get_rtf_files(folder)

Lists RTF files that are candidates for comparison.

compare_rtf_files(file_path1, file_path2, compared_output, summary_output)

Uses Aspose Words to compare two documents and save both a comparison document and a summary.

comparertf(self)

Coordinates comparison of matching current and previous RTF files, writing revision outputs to the report area.

copyguide.py — Topic: Copy the guide reference
copy_file(self)

Copies the reference user guide into the current report/working location so it can be updated safely.

listtxtnew.py — Topic: Identify revised forms
listrevision_txt_files(self)

Builds a text list of files identified as revised.

revised2xlsx(self)

Converts the revised-forms text list to an Excel workbook.

match_form_titles(self) and match_form_titles1(...)

Match revised form records to the current form list so the report includes form-title context.

compare_formlistnew.py — Topic: Find added and deleted forms
compare_formlists(self)

Compares previous and current form-list workbooks to identify changes.

match_form_titles_add(self)

Matches added-form records to titles in the current form list.

match_form_titles_deleted(self)

Matches deleted-form records to titles in the previous form list.

CollectedForms.py — Topic: Assemble report data
process_excel_file(file_path, label)

Reads a report Excel file and formats its contents with a meaningful label.

process_forms(self)

Collects the added, deleted, and revised form report data and writes one CollectedForms.txt file.

ExtractTitle.py — Topic: Read guide title and sample text
extract_forms_title_from_rtf(self)

Converts the user guide RTF content to plain text and extracts the publication-title value needed by the final guide.

extract_forms_sample_from_rtf(self)

Extracts the sample/reference content used when preparing the new guide.

releasenotes.py — Topic: Generate release notes
generate_report(self=None)

Uses the selected month, year, and release information to create the release-notes text report.

deleteMODIFIED.py — Topic: Remove an old temporary guide
delete_modified_userguide_rtf(self)

Deletes the older userguide_MODIFIED.rtf file before a new updated guide is created.

userguideupdate.py — Topic: Build the updated user guide
convert_rtf_to_docx(...) / convert_docx_to_rtf(...)

Automate Microsoft Word through win32com to move between RTF and DOCX for editing.

modify_docx_title, modify_docx_relnotes, modify_docx_title_inpara, modify_docx_sample

Find and replace specific guide content while retaining document formatting where possible.

_modify_docx_section(...), modify_docx_revisenotes, modify_docx_newforms, modify_docx_deletednotes

Reusable section-update logic for revised, newly added, and deleted forms.

userguide_update(self)

The orchestration function: reads report files, updates the DOCX content, converts it back to RTF, and removes the temporary DOCX file.

06 · Developer checklist

Run, package, and extend the application

Run locally

Use Python 3.13 and the project environment:
.\.venv\Scripts\python.exe main.py

Package it

Use Auto Py to Exe in One Directory mode. Include logo.ico and FOD.png as additional files so they remain beside the executable.

Add a new feature

Create a focused module in functions/, import it in main.py, then add it to the appropriate workflow list with a clear progress description.

Important operational note: document conversion relies on Microsoft Word automation through pywin32. A computer running the app needs Microsoft Word installed and accessible to the signed-in user.
